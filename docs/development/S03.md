# S03 work order — workspace edits and undo

S02 implementation pushed and remote-verified at
`8fe242f` (full revision is in Git history); 24 local regression checks and build

## Ownership and intent

Add `core/workspace.py` and `core/edits.py`; adapt file tools, Agent workspace
resolution, MCP root resolution and slash undo. Explicit workspace beats stored
settings; default workspace is the current project directory, as README promises.
File tools validate arguments and contained paths, including symlink/foreign-drive
escapes. Atomic writes record before/after bytes and modes in a workspace-scoped
SQLite journal under application state. Journal entries are prepared before writes
and completed afterward. Undo only restores the last completed agent edit if the
current file still matches its recorded result. Never reset Git or mutate its index.

## Constraints

Preserve tool names and `auto_git_commit` callable compatibility, but file tools
must stop invoking automatic commits. Keep all content and outputs rather than
hard truncation. Preserve binary files on UTF-8 errors. New-file undo removes only
that unchanged agent-created file; an explicit user `/undo` authorizes that inverse
operation. Preserve file modes. Lock the journal across concurrent operations;
refuse ambiguous/empty replacements. Containment is not an OS sandbox, and shell
policy is the next separate S06 boundary.

## Gates

Temporary-workspace tests cover traversal, foreign paths, symlinks, complete
contents, exact replacement, atomic failure and stale undo. Temporary Git repos
prove HEAD/index/unrelated dirty files survive write, replace and undo. No real
user files or provider requests are used. Windows symlink availability is an
explicit test limitation rather than an assumed pass.
