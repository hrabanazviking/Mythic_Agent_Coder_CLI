## Ownership and observed defects

Policy/execution services own permission decisions and cancellable processes.
Runtime, CLI, primary TUI, direct tools and current MCP adapters consume them.
Keep interfaces compatible where possible; document deliberate refusal defaults.

Observed current defects: direct execution permits mutations without a policy;
TUI only asks for shell commands, and its missing-UI fallback approves them.
Other mutations, GitHub tools and current MCP mutators bypass that path. Delegated
agents do not inherit a caller's policy. Shell commands use blocking subprocess.run
and hide nonzero exit codes when output exists. `/stop` enqueues a sentinel but
does not cancel active work. Approval waits cannot be cancelled, and a synchronous
provider read may keep the turn alive after stop. Legacy slash commands also invoke
mutating Git/GitHub/process operations independently of tool permission checks.

## Required behavior

- One decision at the execution boundary covers every tool, before any side
  effect. Preserve schema validation and complete tool-call/result groups.
  Default direct/machine callers to refusal for mutations without explicit policy.
  Read-only, ask and trusted modes have one documented meaning. Missing approval
  UI/callback, EOF and approval timeout reject; they never silently approve.
- Human TUI supplies a cancellable approval callback; CLI supplies its existing
  terminal callback. Existing explicitly selected auto-accept preference maps to
  trusted mode. Permission changes/overrides must be visible and apply consistently.
  Delegation/ghost execution inherits the effective caller policy, without gaining
  privileges from independently loaded defaults. Current MCP writes/delegation
  use a configured explicit machine policy and refuse unattended prompts.
- Legacy mutating slash paths consult the same policy; direct private compatibility
  helpers must not provide a silent no-policy mutation bypass. Central Git scope/
  staging/command routing redesign remains S10, but refusal must work now.
- Add an owned process runner with finite configurable timeout, cancellation,
  complete captured output/progress events, and explicit exit/status results.
  Stop/timeout terminates owned descendants on supported Linux/macOS/Windows
  paths and reaps the process. Preserve outputs before failure/cancellation.
  Never target unrelated processes. Shell use remains explicit trusted/approved
  capability and is not an operating-system sandbox.
- Active provider requests must have a cancellable owned request path; cancellation
  closes/releases the request and leaves no turn executing model/tools afterward.
  Preserve an injectable fake-client seam for credential-free deterministic tests.
  Retry waits remain cancellable. Streaming/capability handling belongs to S07.
- `/stop` cancels active agents and pending approvals/requests/processes rather
  than merely queueing shutdown behind them. A fresh turn can run afterward.
  Full typed task IDs/registry locks/graceful multi-agent shutdown remain S08.
- Cancellation/failure outcomes and partial tool results persist through S05;
  adapters report cancellation/permission refusal honestly. Operational timeout/
  approval/termination defaults live in packaged data, with finite validation.
