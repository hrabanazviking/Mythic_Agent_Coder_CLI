## Ownership and observed defects

Provider services own endpoint/credential admission, request parameters, streamed
message assembly, failure classification and usage. Runtime/CLI/setup consume
them, with S06 retaining owned request cleanup and cancellation.

Current requests always use `stream=False`, and the validated `max_tokens: 127000`
setting is never sent. Missing remote credentials silently become `sk-dummy`.
Capabilities/model limits are unreported, ordinary SDK errors lack actionable
diagnostics, model discovery constructs an Agent just to issue a request, and the
legacy `/cost` invents a blended price. No offline provider diagnostics command
exists; `/doctor` currently means an authorized project subprocess.

## Required behavior

- Central provider configuration validates HTTP(S) endpoint, selected model and
  configured capabilities/budgets. Do not infer provider/model limits from names.
  Report configured support separately from verified support and unknown limits.
  Unknown live capabilities must not be advertised as tested. Explicit text-only
  mode can omit tools; requesting disabled streaming/tool capability fails before
  an inappropriate request. Preserve customized/unknown configuration fields.
- Missing credentials for an authenticated remote endpoint fail before network
  execution with a redacted, useful remedy. Loopback local endpoints may operate
  without auth; explicitly configured anonymous endpoints may opt out. Preserve
  the existing endpoint-key/environment selection; never substitute invented
  remote credentials or provision/spend on hosted accounts during this slice.
- Output-token settings are sent using the configured compatibility field
  (`max_tokens`, `max_completion_tokens`, or explicit omission). Choose a modest
  documented fresh default, preserve existing explicit user overrides, validate
  declared output/model bounds, and never silently truncate stored conversation.
  Context assembly/overflow management remains S11.
- Add optional SSE streaming using the owned asynchronous client lifetime.
  Accumulate text and indexed tool-name/argument fragments into one normalized
  assistant message; tools execute only after the completed response validates.
  Emit incremental text once, retain actual usage, and keep text/result behavior
  compatible for non-streaming providers. Preserve the credential-free fake-client
  injection seam. Malformed/incomplete streams fail without tool execution.
- Stream interruption preserves received text in a durable diagnostic event and
  closes the connection; partial tool fragments never become executable calls.
  Do not retry after emitting a partial response. Pre-response transient 408/409/
  429/5xx/connect/timeout errors have finite cancellable retry budgets, with bounded
  Retry-After when available. Auth/bad model/invalid request/capability failures
  fail promptly. A fresh turn must recover after failure or cancellation.
- Track provider-reported input/output/total usage where supplied, preserve unknown
  values honestly, and report cost as unknown unless explicitly supported by
  configured pricing. Never invent a model price or infer tokens from characters
  as actual usage. Resume must not forget persisted usage totals.
- Add `mythic doctor` for offline configuration/capability diagnostics and explicit
  `--live` model-discovery connectivity. Offline must make no network request or
  start Agent/TUI/memory workers. Live performs an explicitly requested metadata
  request, reports empty/model-missing/auth/failure outcomes, and redacts errors.
  Preserve human `/doctor <command>` compatibility pending S10 routing.
- Setup/model discovery uses the provider service without constructing a temporary
  Agent; local anonymous settings work. Empty discoveries/errors do not falsely
  enable a configured selection. Full screen/lifecycle tests remain S09.
